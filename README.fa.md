# VCNO

**VCNO (Vibe Coding NO)** یک گردش‌کار ساخت‌یافته و مرحله‌به‌مرحله برای توسعه نرم‌افزار با کمک هوش مصنوعی است. این سیستم گفت‌وگو با یک ایجنت کدنویس را به یک فرایند مهندسی کنترل‌شده تبدیل می‌کند — ابتدا بررسی، سپس اعتبارسنجی، برنامه‌ریزی، ساخت، تکرار و مستندسازی — تا توسعه با کمک AI قابل‌فهم، قابل‌تکرار و قابل‌نگهداری باشد.

**نسخه:** v1.0
**مخزن:** https://github.com/MRAVLM/VCNO
**English:** [README.md](README.md)

---

## VCNO چیست؟

VCNO مجموعه‌ای از **مهارت‌های مبتنی بر پرامپت** است که رفتار یک ایجنت کدنویس را در هر مرحله از پروژه مشخص می‌کند. به جای اینکه از AI بخواهید «کل پروژه را بساز»، VCNO کار را به شش مرحله‌ی صریح تقسیم می‌کند:

```text
/init → /check → /PRD → /Build → /Feedback ↺ → /Doc
```

هر مرحله یک مسئولیت دارد و مرزهای سختی برای «چه کاری می‌تواند» و «چه کاری نباید» انجام دهد. نتیجه، گردش‌کاری است که در آن توسعه‌دهنده کنترل را در دست دارد، زمینه‌ی پروژه حفظ می‌شود و نتایج به‌جای فرض‌شدن، تأیید می‌شوند.

## چرا VCNO؟

بیشتر توسعه‌های امروزی با AI بدون ساختار هستند: پرامپتی بزرگ فرستاده می‌شود، ایجنت مقدار زیادی کد می‌نویسد، و هیچ‌کس مطمئن نیست واقعاً چه چیزی کار می‌کند. VCNO این مشکل را با اصول زیر حل می‌کند:

- **قبل از تغییر، بفهم.**
- **قبل از دست‌زدن به پروژه، آن را بررسی کن.**
- **زمینه، فایل‌ها و کارهای موجود را حفظ کن.**
- **فایل، قابلیت، وابستگی و معماری تکراری نساز.**
- **نیازمندی‌های ناشناخته را حدس نزن — بپرس.**
- **فهم، اعتبارسنجی، برنامه‌ریزی، پیاده‌سازی، تکرار و مستندسازی را از هم جدا کن.**
- **نتیجه‌ی واقعی را تأیید کن، نه فرض.**
- **مستندات را با وضعیت واقعی پروژه هم‌راستا نگه دار.**
- **از Git به‌صورت مسئولانه با نقاط ذخیره‌ی معنادار استفاده کن.**
- **از گسترش بی‌کنترل دامنه جلوگیری کن.**
- **انسان را در تصمیم‌های مهم دخیل نگه دار.**
- **با AI مثل یک دستیار مهندسی رفتار کن، نه یک تولیدکننده‌ی کد بی‌کنترل.**

## گردش‌کار VCNO

```text
/init       → درک پروژه و زمینه‌ی آن
   ↓
/check      → اعتبارسنجی نیازمندی‌ها، تشخیص ابهام و ریسک
   ↓
/PRD        → تبدیل فهم معتبر به یک برنامه‌ی آماده‌ی پیاده‌سازی
   ↓
/Build      → پیاده‌سازی برنامه‌ی تأییدشده و تأیید نتیجه
   ↓
/Feedback   → تکرار کنترل‌شده، رفع باگ و بازخورد کاربر    ↺
   ↓
/Doc        → مستندسازی وضعیت واقعی و نهایی پروژه
```

## VCNO چطور کار می‌کند؟

VCNO یک پکیج اجرایی نیست. این سیستم **درون یک ایجنت کدنویس سازگار** به‌عنوان مجموعه‌ای از مهارت‌ها استفاده می‌شود. پروژه را به ایجنت معرفی می‌کنید، `/init` را اجرا می‌کنید و مراحل را به‌ترتیب پیش می‌برید. هر مرحله خروجی مرحله‌ی قبل را می‌خواند، بنابراین زمینه بین گفت‌وگوها از دست نمی‌رود.

> این مخزن به ایجنت خاصی وابسته نیست: هر ابزار از طریق فایل بومی خودش به یک منبع واحد حقیقت می‌رسد (بخش [نقطه‌ی ورود ابزارهای AI](#نقطهی-ورود-ابزارهای-ai)).

## مهارت‌ها

همه‌ی مهارت‌ها در [`skills/`](skills/README.md) هستند؛ هرکدام یک پوشه + یک `SKILL.md`.

| مهارت | مرحله | چه می‌کند | نباید |
|---|---|---|---|
| [`/init`](skills/init/SKILL.md) | درک | مخزن را بررسی، استک/دارایی/داکس/Git را تشخیص می‌دهد؛ سند زمینه‌ی پروژه را می‌نویسد | کد بنویسد، نصب کند، refactor کند، حذف کند |
| [`/check`](skills/check/SKILL.md) | اعتبارسنجی | ایده، نیازمندی‌ها، MVP، امکان‌سنجی، ریسک، تناقض و ناشناخته‌ها را بررسی می‌کند | پیاده‌سازی کند، refactor کند، معماری کامل طراحی کند |
| [`/PRD`](skills/prd/SKILL.md) | برنامه‌ریزی | blueprint محصول/فنی: نیازمندی، جریان، معماری، داده، API، auth، تست، برنامه | پیاده‌سازی کند، نصب کند، بیش‌ازحد مهندسی کند |
| [`/Build`](skills/build/SKILL.md) | پیاده‌سازی + تأیید | PRD تأییدشده را تدریجی پیاده، تست، verify و checkpoint می‌کند | نیازمندی اختراع کند، کد کارآمد را بازنویسی کند، موفقیتِ verifyنشده ادعا کند |
| [`/Feedback`](skills/feedback/SKILL.md) | تکرار ↺ | بازخورد (باگ، UX، فیچر، اسکرین‌شات، صدا) را به بهبود معتبر با محافظت regression تبدیل می‌کند | دامنه را خاموش گسترش دهد، جای برنامه‌ریزی را بگیرد، بی‌پایان loop کند |
| [`/Doc`](skills/doc/SKILL.md) | نهایی‌سازی | مستندات را با پیاده‌سازی واقعی هم‌راستا و آمادگی تحویل/انتشار را ارزیابی می‌کند | فیچر غایب را بسازد، شکاف را پنهان کند، وضعیتِ verifyنشده ادعا کند |

**چرا هرکدام وجود دارد (یک خط):** `/init` تا پیش از تغییر بفهمد · `/check` تا چیزی را که نمی‌فهمد برنامه‌ریزی نکند · `/PRD` تا `/Build` با وضوح شروع کند نه با حدس · `/Build` تا طرح تأییدشده به‌شکل ایمن به نرم‌افزار کارآمد تبدیل شود · `/Feedback` تا بهبود کنترل‌شده باشد نه هرج‌ومرج · `/Doc` تا توسعه‌دهنده‌ی دیگری پروژه را بفهمد، اجرا و نگهداری کند.

## برای چه کسانی مناسب است؟

- توسعه‌دهندگانی که با AI کار می‌کنند و Vibe Coderها
- توسعه‌دهندگان بک‌اند، فرانت‌اند و فول‌استک
- مهندسان AI / ML
- دانشجویان در حال یادگیری توسعه‌ی ساخت‌یافته
- سازندگان استارتاپ، ایندی‌هکرها و بنیان‌گذاران فنی
- تیم‌هایی که از ایجنت‌های کدنویس روی مخزن‌های بلندمدت استفاده می‌کنند

**احتمالاً لازم نیست** اگر فقط اسکریپت‌های کوچک و مستقل می‌نویسید و یک پرامپت کافی است.

## موارد استفاده

- شروع یک اپلیکیشن جدید از یک ایده
- کار روی یک کدبیس موجود یا قدیمی
- افزودن قابلیت یا رفع باگ با کمک AI
- تکرار بر اساس بازخورد واقعی کاربر
- ساخت MVP تحت فشار زمانی
- نگه‌داشتن مخزن‌های بلندمدت قابل‌فهم با ایجنت‌های کدنویس

## VCNO چه چیزی نیست؟

- یک زبان برنامه‌نویسی نیست
- یک فریم‌ورک (Django، FastAPI، Rails و…) نیست
- یک مدل AI نیست
- جایگزین توسعه‌دهنده نمی‌شود
- تضمین نرم‌افزار بدون باگ نمی‌دهد
- جای تست و تأیید را نمی‌گیرد
- نیازمندی‌های ناشناخته را به‌طور خودکار کشف نمی‌کند

## فلسفه‌ی پروژه

> قبل از تغییر بفهم. قبل از برنامه‌ریزی اعتبارسنجی کن. قبل از ساخت برنامه‌ریزی کن. قبل از ادعا تأیید کن. واقعیت را مستند کن، نه نیت را.

VCNO وجود دارد چون توسعه‌ی بی‌ساختار با AI معمولاً زمینه را از دست می‌دهد، کارها را تکراری می‌کند، دامنه را گسترش می‌دهد و کدی می‌سازد که کسی نمی‌تواند نگهداری کند. VCNO با AI مثل یک دستیار مهندسی درون یک فرایند کنترل‌شده رفتار می‌کند.

### نقطه‌ی ورود ابزارهای AI

هر ابزار AI-coding اصلی از طریق فایل بومی خودش این مخزن را می‌خواند — همه به یک منبع واحد حقیقت (`AGENTS.md` + `skills/`) اشاره می‌کنند:

| ابزار | می‌خواند | به کجا اشاره می‌کند |
|---|---|---|
| Codex، Cursor، Zed، Amp و… | `AGENTS.md` | ← منبع اصلی |
| Claude Code | `CLAUDE.md` + `.claude/skills/*/SKILL.md` | `AGENTS.md` + `skills/` |
| GitHub Copilot | `.github/copilot-instructions.md` | `AGENTS.md` |
| Gemini CLI | `GEMINI.md` | `AGENTS.md` |
| Windsurf | `.windsurfrules` | `AGENTS.md` |

### ساختار مخزن

```text
.
├── AGENTS.md      ← نقطه‌ی ورود ایجنت‌ها (منبع اصلی شیم‌ها)
├── CLAUDE.md      ← شیم Claude Code
├── README.md      ← انگلیسی
├── README.fa.md   ← همین فایل (فارسی)
├── .claude/skills/   ← شیم اسکیل‌ها برای Claude Code
├── .github/copilot-instructions.md
├── GEMINI.md / .windsurfrules
├── skills/        ← شش مهارت VCNO (منبع حقیقت) + _template/
├── backend/       ← سرور و API
├── frontend/      ← رابط کاربری
└── docs/          ← مستندات پروژه
```

## آموزش

> ⏳ **بخش آموزش هنوز نوشته نشده** — در پایان‌کارِ داکس‌ها و اسکیل‌ها اینجا قرار می‌گیرد.

محتوای برنامه‌ریزی‌شده:

1. وایپ‌کدینگ چیست و چطور بدون دانش عمیق کدنویسی نتیجه بگیریم
2. چطور از `AGENTS.md` شروع کنیم
3. چطور یک اسکیل بسازیم و اجرا کنیم (قدم‌به‌قدم با مثال واقعی)
4. چطور داکس‌های پروژه را بخوانیم و به‌روز نگه‌داریم
5. یک پروژه‌ی کوچک عملی: از صفر تا اجرا با کمک اسکیل‌ها
