# 🏗️ معماری پروژه (Architecture)

> **برای چه کسی؟** هرکسی که می‌خواهد **تصویر کلی** مخزن را ببیند — چه چیزی واقعاً وجود دارد، چه چیزی فقط برنامه‌ریزی شده.
> **چه زمانی؟** قبل از هر تغییر بزرگ.

## چرا این سند مهم است

این مخزن دو لایه‌ی کاملاً متفاوت دارد که نباید با هم قاطی شوند:

1. **واقعاً پیاده‌شده:** سیستم مهارت‌های VCNO + مستندات + خط لوله‌ی اعتبارسنجی
2. **فقط برنامه‌ریزی‌شده:** اپلیکیشن بک‌اند/فرانت‌اند (هنوز کدی ندارد)

## لایه ۱ — آنچه واقعاً وجود دارد

```text
                     ┌─────────────────────────────────────┐
   ایجنت‌های AI       │   منبع واحد حقیقت (Source of Truth) │
 ┌──────────────┐     │                                     │
 │ Codex/Cursor │────▶│  AGENTS.md  ← نقطه‌ی ورود اصلی      │
 │ Zed/Amp ...  │     │  skills/    ← ۶ مهارت VCNO + الگو  │
 ├──────────────┤     │  docs/      ← مستندات پروژه         │
 │ Claude Code  │────▶│  README.md / README.fa.md          │
 │  (CLAUDE.md  │     └─────────────────────────────────────┘
 │  + .claude/  │                    ▲
 │   skills/)   │                    │ فقط اشاره می‌کنند،
 ├──────────────┤                    │ کپی نمی‌کنند
 │ Copilot /    │──── شیم‌هایی که    │
 │ Gemini /     │    به بالا می‌روند  │
 │ Windsurf     │                    │
 └──────────────┘     .github/copilot-instructions.md
                      CLAUDE.md · GEMINI.md · .windsurfrules
                      .claude/skills/*/SKILL.md
```

**قانون طلایی معماری:** محتوا فقط در `AGENTS.md` و `skills/` نوشته می‌شود؛ فایل‌های ابزارها شیم (pointer) هستند و هرگز جداگانه ویرایش نمی‌شوند — همین باعث می‌شود یک تغییر، در همه‌ی ابزارها اعمال شود.

### جریان context در خط لوله‌ی VCNO

```text
/init ──▶ docs/project.md + docs/logs/init.md
              │
/check ──◀────┴──▶ رکورد اعتبارسنجی (readiness)
   │
/PRD ────────────▶ docs/PRD.md (blueprint + برنامه‌ی اجرا)
   │
/Build ──────────▶ کد + تست + checkpoint     ◀── اولین مرحله‌ی مجازِ تغییر کد
   │
/Feedback ───────▶ آیتم‌های FB-NNN (حلقه ↺)  ◀── کد + بازخورد
   │
/Doc ────────────▶ داکس هم‌راستا با واقعیت   ◀── فقط داکس
```

هر مرحله خروجی مرحله‌ی قبل را می‌خواند؛ برای جزئیات رفتار هرکدام، [`../skills/`](../skills/README.md).

### خط اعتبارسنجی (CI)

```text
هر push / pull request
   └──▶ GitHub Actions: .github/workflows/validate.yml
              └──▶ python3 scripts/validate.py
                     ├── فرانت‌متر همه‌ی SKILL.md ها
                     └── لینک‌های نسبی مارک‌داون
```

## لایه ۲ — آنچه فقط برنامه‌ریزی شده (هنوز کد ندارد)

> ⚠️ هیچ فایل کدی در `backend/` یا `frontend/` جز README وجود ندارد — **این بخش آینده است، نه حال.**

```text
کاربر
  │
  ▼
┌──────────────┐     HTTP/JSON     ┌──────────────┐      ┌──────────────┐
│   frontend/  │ ────────────────▶ │   backend/   │ ───▶ │   Database   │
│ (React+Vite) │ ◀──────────────── │  (Fastify)   │      │ (PostgreSQL) │
└──────────────┘                   └──────────────┘      └──────────────┘
```

| بخش | پشته‌ی پیشنهادی | وضعیت |
|---|---|---|
| [`../backend/README.md`](../backend/README.md) | TypeScript · Fastify · PostgreSQL+Prisma · Vitest | 🟡 فقط README |
| [`../frontend/README.md`](../frontend/README.md) | TypeScript · React+Vite · Tailwind · TanStack Query | 🟡 فقط README |

**قاعده‌ی طلایی کد (وقتی scaffold شد):** بک‌اند `route → service → db`؛ فرانت‌اند `page → component → api`.

## تصمیم‌های معماری (ADR)

| تصمیم | چرا؟ | وضعیت |
|---|---|---|
| TypeScript در هر دو بخش | فقط یک زبان برای تازه‌کارها | ✅ تأییدشده در READMEها |
| منبع واحد حقیقت = `AGENTS.md` + `skills/` | جلوگیری از پراکندگی و کپی بین ابزارها | ✅ اجراشده |
| شیم برای هر ابزار، بدون کپی محتوا | سازگاری با همه‌ی ایجنت‌ها با یک ویرایش | ✅ اجراشده |
| اعتبارسنجی خودکار در CI | لینک‌ها و فرانت‌مترها قبل از merge سالم بمانند | ✅ اجراشده |
| پشته‌ی بک‌اند/فرانت‌اند نهایی | بعد از `/check` و `/PRD` تصمیم گرفته می‌شود | ⏳ در انتظار |
