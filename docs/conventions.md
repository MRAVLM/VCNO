# 📐 قواعد کدنویسی (Conventions)

> **برای چه کسی؟** هرکسی (انسان یا ایجنت) که می‌خواهد در این پروژه **کد بنویسد**.
> **چه زمانی؟** قبل از نوشتن هر کد جدید — ۳۰ ثانیه مرور کافی است.

## زبان و نام‌گذاری

| مورد | قاعده | مثال درست | مثال غلط |
|---|---|---|---|
| نام فایل | kebab-case انگلیسی | `user-service.ts` | `UserService.tsx` |
| نام متغیر/توابع | camelCase | `getUserById` | `get_user_id` |
| نام کلاس/تایپ | PascalCase | `UserProfile` | `user_profile` |
| ثابت‌ها | UPPER_SNAKE | `MAX_RETRY` | `maxRetry` |
| کامیت | انگلیسی، فعل محور | `add user login` | `Update` |

## ساختار کد

- **بک‌اند:** `route → service → db` — منطق هرگز داخل route نوشته نشود.
- **فرانت‌اند:** `page → component → api` — `fetch` فقط داخل `frontend/src/api/`.
- هر فایل بیشتر از ~۳۰۰ خط نشود؛ اگر شد، تقسیمش کن.

## کامنت‌نویسی

- کامنت **فارسی** فقط برای «چرا؟» — نه «چه چیزی؟» (کد خودش باید بگوید چه می‌کند).
- کدی که نیاز به کامنت زیاد دارد، احتمالاً باید بازنویسی شود.

## تست و کیفیت

- هر تابع منطقی حداقل یک تست دارد.
- **قبل از پایان کار:**
  ```bash
  npm run typecheck
  npm run test
  ```
